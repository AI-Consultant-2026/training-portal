### Admin stats dashboard (implemented and verified, not yet committed)

Plan approved and saved at `.claude/plans/recursive-giggling-cocke.md` (overwritten again — different task). Before this, "admin" was essentially "super-instructor": every admin capability either mirrored an instructor one or was a single ownership-bypass check scattered across services — no admin-only reporting surface existed at all (confirmed via exploration: no user list endpoint, no aggregate counts anywhere, no admin frontend page beyond the student dashboard). User explicitly chose scope ("full stats dashboard" with real new aggregation) and visuals (plain Tailwind stat tiles, no charting library) via AskUserQuestion before planning.

- **Backend**: new `admin.service.ts`'s `getDashboardStats()` — the first place in this codebase using SQL aggregation (`GROUP BY`, `AVG`); everything built before this only ever returned full row lists. Handles a real gotcha a Plan-agent review caught before implementation: Postgres returns `COUNT`/`AVG` as numeric *strings* through the raw driver on grouped/raw queries (confirmed no `pg.types` customization exists anywhere in this repo), so every aggregate value needs an explicit `Number(...)` conversion and a `null`-before-`Math.round` guard (Postgres `AVG()` over zero/all-null rows returns SQL `NULL`, not `NaN`). Quiz pass-rate is deliberately computed in JS after loading graded attempts with their quiz (`include`), not via a cross-table SQL `col()` comparison — that construct has a documented footgun (needs the literal snake_case joined-table identifier, not the JS attribute name) with zero precedent anywhere in this codebase, and there's no real performance need to push it into SQL at this app's scale. New route `GET /api/admin/stats` is `authorize("admin")` **only** — the first exception to this app's established "admin = instructor-superset" pattern (every other admin-touching route allows instructor too); locked in with a dedicated 403-for-instructor test. 8 new integration tests in `admin.test.ts` (auth/role gating, a hand-verified fixture with exact expected numbers, and an empty-DB edge case asserting `null`/`0` not `NaN`/crash). All 60 backend tests pass.

New `AdminDashboardPage.tsx` with sections for users/courses/enrollments/assignment-grading/quiz-grading, the pending-grading tiles linking out to the *existing* instructor grading-queue pages rather than rebuilding list UIs. New admin-only route `/admin` (its own `RoleRoute allowedRoles={["admin"]}` block, distinct from the existing instructor+admin one). ## Auth rate limiter note
The Phase 1 auth rate limiter (20 req/15min on `/api/auth/*`) is real and correctly protects production, but it WILL block rapid manual curl-based testing/smoke-testing in this same session (confirmed it happened once already). It's skipped automatically when `NODE_ENV=test` (Jest), but manual curl testing against the dev server can still hit it — if that happens, `docker compose restart backend` clears the in-memory counter. Prefer testing via the browser UI (one request per action) over rapid-fire curl loops when possible.

## Backend API reference for the frontend work (all built and tested)
- `GET /api/modules/:id/assignments`, `GET /api/assignments/:id`, `POST /api/assignments/:id/submit` (multipart, field `submissionText` + optional file field `file`), `GET /api/assignments/:id/submissions/:submissionId`, `GET /api/assignments/:id/submissions` (instructor/admin), `PATCH /api/assignment-submissions/:id/grade` (body `{score, feedback}`), `GET /api/instructor/ungraded-submissions`
- `GET /api/modules/:id/quizzes`, `GET /api/quizzes/:id`, `POST /api/quizzes/:id/start` (returns `{attempt, quiz, questions}`, questions never include `isCorrect`), `POST /api/quizzes/:id/submit` (body `{attemptId, responses: [{questionId, studentAnswer}]}` where `studentAnswer` is the selected answer's id for multiple_choice/true_false; returns `{attempt, responses, timedOut, passed}`), `GET /api/quizzes/:id/attempts/:attemptId`, `GET /api/quizzes/:id/attempts` (returns `{attempts, bestScore}`)
- `GET /api/modules/:id/lessons`, `GET /api/lessons/:id` (both public, no auth), `GET /api/lessons/:id/my-completion` (student, returns `{completed}`), `POST /api/lessons/:id/mark-complete` (student, active enrollment required, idempotent, returns `{completed, alreadyCompleted, courseProgress: {totalLessons, completedLessons, progressPercent}}`), `GET /api/courses/:id/progress` (student, any enrollment status, returns `{totalLessons, completedLessons, progressPercent, completedLessonIds}`)
- `GET /api/admin/stats` (admin only, not instructor) — returns `{users: {total, byRole}, courses: {total, byStatus, list: [{id,title,status,enrollmentCount}]}, enrollments: {total, byStatus, averageProgressPercent}, assignments: {totalSubmissions, pendingGrading, graded, averageScore}, quizzes: {totalAttempts, pendingGrading, graded, averageScore, passRate}}`
